## 계약
명시적 cwd(`.` 포함)가 우선한다. 생략했을 때만 대화·프로젝트·서버·제품 기본값 순으로 해석한다. 기준은 `sessions::exec_root`의 실제 실행 root이며 worktree도 따른다.
최초 계획 때 cwd를 target에 고정하고 승인 뒤 설정 변경으로 다시 해석하지 않는다. 직접 작업의 같은 키 replay도 cwd 재적용·중복 프로세스 실행이 없어야 한다.
기존 경계/디렉터리 검증·인증 재검사·프로젝트 lease·read_only/deny·receipt·result_unknown·재시작 복구를 재사용한다.
터미널·hook·외부 CLI cwd는 바꾸지 않는다. 새 dependency·실제 서비스/외부 모델 호출은 금지한다.

## 완료
설정한 기본 위치가 실제 foreground/background 셸과 직접 작업에 적용되고, 명시값·승인 후 변경·worktree·탈출 거부·응답 유실 복구에서도 실행 위치가 일관된다. Windows/macOS 실측과 SETTINGS-011 전체 완료는 별도로 판단한다.

## 기존 세션 브라우저 인수 후속
기존 `642d5bb`·기준·소유권·유효한 Rust 42개와 Vitest·타입 근거를 보존한다. 기존 세션에서 `web/e2e/exec-cwd.spec.ts`, `web/e2e/exec-settings.spec.ts`, `web/e2e/task-start.spec.ts`, `web/e2e/project-scripts.spec.ts`의 정확한 선택 실행과 자기 결함 수정까지 맡는다. 마지막 두 spec은 기존 시나리오·계약을 유지하는 locator/기능 영향 수정만 소유한다.
원본 COMMON의 공유 환경·공유 target·전체 명령 flock을 적용한다. 새 설치·다른 검사 중단·포트 변경·타 worktree 동기화는 하지 않는다. Windows/macOS 실측은 실제 외부 미검증으로 보존하며 Linux에서 가능한 잔여를 끝낸다.
최신 COMMON을 실제 읽고 `grove-handoff:v1`에 실행 가능한 잔여·실제 blocker·통합 담당의 공통 경계 인수를 구분한다. 관련 코드·시험·RESULT만 한국어 로컬 커밋 후 종료하며 메인은 같은 소유 범위를 편집하지 않는다.
