## 목표·실제 경로
`FILEUI-009`: Git 화면에서 현재 branch/detached/unborn·프로젝트와 worktree 관계·정확한 head에 대응하는 PR/CI 상태·현재 실행 가능한 작업과 제한 이유를 확인한다. PR 생성/merge·CI 재실행·로그인·fetch·설치·원격 변경은 하지 않는다.
현재 `src/git.rs::status/branches`와 `src/worktrees.rs::list`는 인증된 프로젝트 read guard와 시스템 Git을 사용한다. `web/app/components/GitPanel.tsx`는 branch와 변경 목록·기존 변경 작업을 표시한다. `src/repos.rs::search`는 `Config::gh_command`로 서버의 GitHub CLI를 사용하고 missing/unauthenticated/error를 구분하며 토큰을 보관하지 않는다. 이 계약을 재사용한다.

## 소유권
- 신규 `src/git_context.rs`, `tests/git_context.rs`, `web/app/components/git-context/`, `web/app/api/gitContext.ts`, `web/e2e/git-context.spec.ts`, `work/RESULT-42.md`.
- `src/lib.rs`의 전용 모듈·프로젝트 읽기 route 등록만 소유한다. `src/git.rs`·`repos.rs`·`worktrees.rs`는 재사용 가능한 조회 helper의 좁은 export만 허용하고 기존 조회/변경 동작은 바꾸지 않는다.
- `GitPanel.tsx`는 import와 개요 mount·현재 projectId/갱신 신호 전달만 소유한다. 변경 작업은 정확한 기존 서버 권한/상태가 확인된 경우에만 제약 이유를 표시하도록 좁게 연결할 수 있다. 기존 fingerprint·revision·미확정 요청·확인 dialog·hunk/stash/원격 작업의 의미는 유지한다.
- 서버 권한/설정 조회는 기존 인증·read_only·프로젝트 상태 정본을 사용한다. 설정·승인 정책을 새로 만들지 않는다. 공용 API client·state·CSS·runner·store/migration·dependency·TODO는 수정하지 않는다.

## 고정 계약
조회는 index/HEAD·원격·worktree 등록을 바꾸지 않는다. shell 문자열을 만들지 않고 고정 argv를 사용한다. remote userinfo/token·인증 헤더·서버 개인 경로·원격 오류 원문을 화면/로그로 유출하지 않는다. 임의 remote URL을 HTTP 요청 대상으로 사용하지 않는다.
GitHub 조회는 기존 고정 gh 실행 경로와 검증된 repo identity를 사용하고 현재 head를 확인한다. branch 이름만 같은 오래된 PR/CI를 현재 결과로 표시하지 않는다. 응답 중 head/프로젝트 변경은 stale로 구분한다. GitHub가 아닌 remote·CLI 부재·미인증·timeout·접근 거부·결과 없음은 각각 표시하고 성공/실패를 추측하지 않는다. 토큰 수집·자동 로그인·설치는 하지 않는다.
기존 서버 변경 API가 최종 권한 정본이다. UI 표시를 승인으로 삼거나 조회가 실행을 일으키면 안 된다. PWA offline 차단 이유와 read_only/기기 권한·detached/dirty 등 개별 작업 제한을 혼동하지 않는다. 다른 프로젝트/늦은 응답·재접속에서도 이전 상태를 새 대상으로 표시하지 않는다.

## 검증·완료
로컬 격리 Git/gh fixture로 일반 branch·detached/unborn·linked worktree·권한 거부·미지원 remote·CLI 오류·head 경합·다른 프로젝트 접근 차단을 확인한다. 실제 외부 GitHub 계정·원격 저장소·사용자 자격은 사용하지 않는다. 배정된 브라우저는 `e2e/git-context.spec.ts`의 개요 조회·상태 변화·제한 이유와 기존 Git 입력/미확정 요청 보존 흐름이다.
COMMON의 공유 환경과 전체 Rust/E2E 명령 잠금을 따른다. 완료는 정확한 위치/PR/CI/권한을 실제 조회 경로에서 확인하고 unknown/stale/unsupported를 사실과 구분하는 사용자 흐름이다. 실행 가능한 소유 잔여·브라우저 인수를 끝내고 RESULT의 `grove-handoff:v1`에 실제 근거·blocker(reason/unblock)를 남긴다. 한국어 관련 로컬 커밋은 허용하며 merge·push·배포·재위임·workspace 정리·TODO 체크는 하지 않는다.
