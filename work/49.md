## 사용자 흐름·소유
재개방한 `LAYOUT-004`의 분할 생성 자체에서 설정 초안이 유실되는 결함을 끝낸다. `SplitView`는 `NodeView`에 split tree를 넘기며 leaf→split 전환 때 기존 `PaneView` 하위 트리가 remount된다. 탭 ID가 유지돼도 컴포넌트 local state 수명은 보장되지 않는다. 기존 최근 탭/분할/이동 동작과 서버 실행을 보존한다.
소유는 `web/app/components/SplitView.tsx`, 필요 시 신규 `web/app/components/pane-lifetime/` 모듈·단위 시험, 신규 `web/e2e/pane-draft-lifetime.spec.ts`, 기존 `web/e2e/pane-dnd.spec.ts`의 관련 회귀, `work/RESULT-49.md`다. `web/app/app.css`는 `.split-root`·`.split`·`.split-child`·`.divider`·`.pane` 배치 규칙의 수명 보존 구조에 꼭 필요한 변경만 허용한다.
`Settings`·`ScopedSettings`·`ExecSettings`의 저장/revision/초안·직접 링크 hook, 서버/API/schema, layout 저장 모델, 공통 fixture·다른 기능 화면은 읽기 전용이다. 다른 진행 작업의 Settings 편집과 겹치지 않는다. 실제 필수 연결이 이 범위를 넘으면 정확한 재현·필요 연결을 blocker로 남기고 독립 범위를 끝낸다.

## 보존·완료
분할 전에 설정을 편집하고 분할 생성·방향 변경·탭 이동·반대 pane 닫기 후에도 미저장 값과 고정 project/session 대상이 유지돼야 한다. 자동 저장·서버 재전송·초안의 서버/공용 영구 저장이나 무음 폐기로 우회하지 않는다. 서로 다른 pane/tab의 초안을 섞지 않고 실제 닫은 자원의 수명은 정상 종료한다.
키보드·초점·구분선 조절·narrow 단일 pane·최대화·drag/drop·기존 접근성을 보존한다. 새 라이브러리·의존성·불필요 애니메이션은 추가하지 않는다. UI 규칙을 읽고 기존 패턴을 따른다.
원래 실패를 실제 브라우저에서 먼저 재현하고 수정한 뒤 전용 E2E와 `pane-dnd.spec.ts`, `workspace.spec.ts:44`, `workspace.spec.ts:740`, `workspace.spec.ts:765` 및 관련 layout 단위/타입을 선택 검증한다. 동일 입력의 유효 근거는 반복하지 않는다. 모든 Rust/E2E 전체 명령은 COMMON의 공유 잠금을 유지한다.
완료는 분할 구조 변경이 기존 설정 초안을 버리거나 다른 대상으로 적용하지 않는 상태다. 구현·연결·선택 검사·자기 결함 수정을 끝내고 `grove-handoff:v1`·검증·blocker(reason/unblock)를 RESULT에 남긴다. 관련 한국어 로컬 커밋 허용. TODO 체크·merge/rebase·push·배포·재위임·workspace 관리·dependency 변경은 하지 않는다.
