## 사용자 흐름·실제 연결
`UI-002`의 welcome·온보딩·서버 연결·계정 설정·첫 프로젝트 흐름을 기존 기능으로 완결한다. `Login`은 토큰 로그인과 `PairingLogin`, `Hosts`를 제공하지만 별도 환영/시작 안내가 없고 `Workspace`의 빈 프로젝트 상태는 “프로젝트를 추가하세요.”뿐이다. 처음 연 사용자가 현재 연결 대상·인증 방식·기기 계정 맥락을 확인하고 첫 프로젝트를 명시적으로 추가해 입력창에 도달하게 한다.
로그인과 기기 등록은 기존 `auth/browser-login`, `auth/pairing`, `auth/whoami`를 그대로 쓰며 별도 계정/비밀번호/외부 OAuth/과금 체계는 만들지 않는다. 서버 연결은 기존 `Hosts`와 origin·연결 상태를 재사용한다. 첫 프로젝트는 Workspace의 `setAdding`, `CreationEntry`, `AddProjectDialog`(`/projects`, `/fs/dirs`) 및 `projectAdded`→`startProject`를 재사용한다. 기존 만들기 UI를 복제하거나 새 프로젝트를 자동 생성하지 않는다.

## 소유·비소유
신규 `web/app/components/onboarding/`의 안내/상태·전용 단위 시험, `web/e2e/first-project-onboarding.spec.ts`, `work/RESULT-50.md`를 소유한다. `web/app/components/Login.tsx`는 기존 form/Hosts/PairingLogin을 보존하는 환영·접속 대상·인증 안내 mount, `Workspace.tsx`는 인증/프로젝트 조회 상태를 기존 데이터에서 넘기는 onboarding import/mount와 기존 첫 프로젝트/설정 진입 callback 연결만 허용한다.
기존 `AddProject.tsx`, `create/CreationEntry.tsx`, `create/creation.ts`, `Hosts.tsx`, `Pairing.tsx`, auth/client/store/device/layout, 서버·DB/schema·CSS·Settings·SplitView·다른 기능은 읽기 전용이다. 사용자 흐름의 필수 연결이 부족하면 정확한 위치·최소 변경을 인계하고 독립 범위를 끝낸다. 진행 중 37/41/43 및 준비 49의 소유 파일/함수를 건드리지 않는다.
프로젝트 목록 loading/error를 빈 목록으로 오인해 온보딩 완료/첫 프로젝트 안내를 표시하지 않는다. 로그인 만료/기기 폐기와 최초 미인증을 구분하고 저장된 연결·초안·설정은 지우지 않는다. 토큰은 기존 메모리/HttpOnly 계약을 유지하고 URL·localStorage·로그·fixture에 실제 비밀을 남기지 않는다. 오프라인/호환성 차단은 기존 PWA guard·버튼 이유를 재사용하며 복구 후 자동 로그인/등록/생성/전송하지 않는다.
