## 실제 경로·소유
기존 `FRAME-005`를 실제 WebSocket 경로에서 검증·완결한다. 현재 경로는 `POST /terminals/{id}/ticket`→`GET /terminal-ws/{ticket}`다. `terminals::{ticket,ws,session,subscribe}`는 일회용 티켓·principal 재검사·1 MiB 메시지 한도·느린 클라이언트 reset을 사용한다. `tests/terminals.rs`의 io/resize/일회성·flood/reset·재시작 lost 근거를 재사용한다.
소유는 신규 `tests/websocket_boundaries.rs`, `src/terminals.rs`의 ticket/ws/session/subscribe와 관련 티켓·queue 상수의 재현된 인증/한도 결함 최소 수정, `work/RESULT-48.md`다. 기존 terminals 시험은 해당 회귀만 확장할 수 있다. auth/revalidate·프로젝트 read guard는 기존 공개 helper를 사용하고 인증 정책·route/middleware·PTY 생성/종료·capture·터미널 UI·공용 client·migration·dependency는 바꾸지 않는다.
host/project/session 권한은 현재 자원 모델의 실제 연결을 기준으로 검증한다. terminal에 없는 세션 소유권이나 새 RBAC 정책을 만들어 요구를 충족했다고 주장하지 않는다. 더 넓은 미연결 FRAME-005 요구는 정확한 근거/해제 조건을 인계한다.

## 안전·실제 인수
실제 업그레이드 거부와 메시지별 재검사, 티켓 만료/중복/다른 대상·권한 철회, 과대/잘못된 프레임·input/resize·queue 지연·재접속을 소유 loopback 서버/PTY에서 확인한다. 단순 HTTP 오류만으로 열린 socket의 철회/메시지 검증을 대체하지 않는다.
재접속은 새 유효 티켓과 현재 snapshot을 받으며 누락 출력을 중복 shell 입력으로 재실행하지 않는다. slow/flood 클라이언트가 서버나 다른 소켓을 무한 대기/무한 queue로 만들면 안 된다. 기존 원문/화면·TTS/마이크 차단과 터미널 키보드 의미를 유지한다.
실제 사용자 shell·다른 세션·공유 서비스·자격증명은 사용하지 않는다. 호스트 origin/auth 제한을 낮추거나 네트워크 노출·포트 변경을 하지 않는다. 선택 Rust websocket_boundaries와 영향을 받은 terminals 회귀를 실제 socket fixture로 검사한다. UI 변경 없는 프로토콜 인수에 별도 브라우저 구현은 필요 없다. COMMON의 공유 환경·전체 Rust/E2E 잠금을 따른다.
완료는 실제 terminal socket이 권한/한도/재접속에서 기존 실행과 자원을 보존하는 상태다. 실행 가능한 잔여를 끝내고 RESULT에 `grove-handoff:v1`·근거·실제 blocker(reason/unblock)를 남긴다. 관련 한국어 로컬 커밋 허용. TODO·merge/rebase·push·배포·재위임·workspace 관리·dependency 변경은 하지 않는다.
