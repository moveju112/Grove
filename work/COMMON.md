# b01 기능 담당 공통 계약

## 시작 즉시 독립 구현
이 파일과 자기 번호 문서, 적용되는 프로젝트·공통·UI 규칙을 읽는다.
현재 cwd·브랜치·Git 상태와 자기 번호 문서의 기준 SHA에서 분기했는지 확인한다. 초기 00~09는 `c186b31ab62734c9f91803cf7848b639ad9871fb`이며, 이후 번호는 번호 문서에 새 기준을 명시한다.
자기 worktree가 아니거나 출처 불명 변경이 있으면 편집하지 말고 구체적 blocker를 보고한다.
올바른 worktree에서는 추가 계획 승인을 기다리지 말고 배정 범위를 구현한다.
다른 세션·통합 담당에게 실시간 메시지·슬롯·승인을 요구하지 않는다.
새 공통 변경·계약 충돌은 해당 부분만 보류하고 독립 범위를 끝낸 뒤 인계 파일에 모은다.
핵심 범위 전체가 막히면 blocker를 기록하고 종료한다. 임의로 다른 기능을 맡지 않는다.

## 편집 소유권
번호 문서의 경로·공통 파일 연결 지점과 자기 `work/RESULT-NN.md`만 수정한다. 다른 경로는 읽기만 가능하다.
번호 문서가 연결 지점을 지정했다면 그 범위의 등록·라우트·화면 mount를 직접 연결해 기능이 실제 경로에서 동작하게 끝낸다. 다음 공통 파일은 번호 문서에 지정된 지점만 수정한다. 과거 배정의 미지정 연결은 메인이 맡되, 신규 배정의 필수 연결 누락은 메인이 소유권을 보완해 원래 담당이 끝내게 한다:
`TODO.md`, `AGENTS.md`, `src/lib.rs`, `src/store.rs`, `src/runner.rs`, `src/tools/mod.rs`,
`web/app/components/SessionView.tsx`, `web/app/components/Composer.tsx`, `web/app/components/Settings.tsx`,
`web/app/state/store.ts`, `web/app/api/`, `web/app/app.css`,
dependency/lockfile, 공통 빌드·E2E 설정, migration.
소유 파일 목록에 명시한 기존 파일 외에는 기존 파일을 수정하지 않는다.
전용 폴더 안 파일은 필요에 맞게 추가할 수 있으나 이름만 맞춘 범위 밖 기능은 넣지 않는다.
새 dependency·업그레이드·원격 설치는 하지 않는다. 필요성을 인계한다.
실제 파일을 재사용할 수 없다는 이유로 동일 구현을 복제하거나 보안을 낮추지 않는다.

## workspace에서 끝낼 일
- 신규 배정은 모듈 제작이 아니라 실제 사용자 흐름의 구현·연결·시험·자기 변경 검토까지 포함한다. 번호 문서가 허용한 공통 연결 지점도 직접 완성한다. 통합 담당에게 구현을 넘기기 위해 연결을 생략하지 않는다.
- API·권한·오류·복구 계약과 기존 호출자를 먼저 확인하고, 자기 변경의 선택 Rust·Vitest·typecheck 및 통합 담당이 실행할 E2E 시나리오를 준비한다. 소유 범위 안에서 발견한 결함은 직접 수정하고 실패·영향 검사만 재실행한다.
- 통합 담당은 전체 인계·코드를 다시 조사하지 않아도 되도록 RESULT에 변경 경로·연결 지점·검사 입력과 결과·남은 조건을 모은다. 선택 검사를 통과한 코드와 재현 가능한 실패를 구분한다.
- 배정된 필수 연결이 소유 범위에 빠졌다면 정확한 함수·호출 경로와 필요한 최소 변경만 인계한다. 다른 workspace나 원본을 수정하거나, 진행 중 반복 메시지로 소유권을 조율하지 않는다. 메인은 후속 배정에서 같은 누락을 반복하지 않는다.
- 실행 한도와 완료 큐는 메인이 관리한다. 이미 시작한 기능은 계속 진행하며 직접 슬롯·merge·workspace 관리 잠금을 얻으려 하지 않는다.
- 메인이 고정 candidate 검증에서 결함을 돌려주면 해당 SHA·선택 검사·실패 로그와 자기 소유 경계를 기준으로 수정한다. 다른 기능의 대기·실패 때문에 독립적인 맡은 작업을 멈추지 않는다. 실패 근거를 삭제하거나 전체 인수를 통과했다고 바꾸지 않는다.
- 맡은 범위에 승인된 실행 가능한 구현·연결·시험·실패 수정이 남으면 부분 완료 보고로 턴을 끝내지 않고 계속한다. 단위 검사 통과·커밋·시간 경과는 종료 조건이 아니다. 막힌 일부와 독립적으로 가능한 일은 먼저 끝낸다.
- 환경 문제는 공통 계약의 기존 툴체인·공유 node_modules·symlink 복구 경로부터 실제로 확인한다. 확인 가능한 복구 없이 부재를 추정하거나, 권한 밖 설치·의존성 추가로 우회하지 않는다. 같은 결정적 실패를 그대로 반복하지 않는다.

## 공통 연결 방식
Rust 전용 모듈은 기존 `ToolResult`·`ToolError`·`Planned`와 권한 경계를 재사용한다.
공통 등록이 없어 컴파일 그래프에 아직 들어가지 않는다면 이를 인계에 명시한다.
도구용 모듈의 기본 연결은 기존 registry의 plan/execute 형태를 따른다.
기존 계약과 다르면 명시적 차이를 남긴다. 통합되지 않은 임시 standalone crate·가짜 실행기를 만들지 않는다.
웹 신규 컴포넌트는 typed props/callback으로 외부 상태·행동을 받는다.
공통 API·store를 바꾸거나 존재하지 않는 API를 실제로 호출해 완성처럼 보이게 하지 않는다.
초기 00·01의 조회 UI 연결 유예는 과거 배정에만 적용한다. 신규 배정에는 실제 서버·화면 연결 경로를 포함한다.
인계에는 export·입출력·오류·필요 호출 위치와 미연결 조건을 적는다.

## 검증·자원
독립 조사·관련 편집은 묶고 유효한 근거는 재사용한다. 보안·오류·복구 분기를 생략하지 않는다.
실시간 자원 조율은 하지 않는다. 전체 회귀·release·패키징은 통합 단계에서 실행한다. 선택 E2E는 기본적으로 통합 인수지만, 메인이 정확한 spec과 검증 소유권을 배정한 경우 기능 workspace에서 끝낼 수 있다.
완료 직전 자기 기능의 선택 Rust 시험(컴파일 포함)과 Vitest·typecheck를 프로젝트 선택 검사 진입점으로 한 번 실행한다. 컴파일되지 않는 코드를 인계하지 않는다. 실패는 고친 뒤 실패한 검사만 다시 실행한다.
worktree에는 Rust 툴체인(`.dev`)과 `web/node_modules`가 없다. 설치·복사하지 말고 메인 것을 쓴다:
- Rust: `source /data/project/paseodog_opus/.envrc.dev`. 자기 worktree의 `.envrc.dev`가 `$PWD/.dev`를 가리키는 옛 버전이어도 이 절대 경로를 source한다.
- 공유 환경 보존 수정 전의 `build.py`를 쓰는 미시작 workspace는 `.dev`가 없는 것을 확인한 뒤 `ln -s /data/project/paseodog_opus/.dev .dev`로 기존 공유 툴체인을 연결할 수 있다. 이미 존재하는 `.dev`나 실행 중인 검사·설치 환경은 바꾸지 않는다. 수정된 실행기는 명시적 `CARGO_HOME`·`RUSTUP_HOME`·`CARGO_TARGET_DIR`를 보존하며 다음 검사부터 사용한다.
- 웹: `web/node_modules`가 없으면 `ln -s /data/project/paseodog_opus/web/node_modules web/node_modules`. Git ignore 대상이라 worktree는 clean으로 남는다. `npm install`·`npm ci`는 하지 않는다.
- Rust 검사는 여러 세션이 동시에 빌드하지 않도록 `flock /home/ubuntu/.cache/grove-rust-check.lock python3 scripts/build.py test --rust ...`로 실행한다. Vitest·typecheck는 잠금 없이 실행한다.
- 여러 Rust target은 `--rust target1 target2`처럼 한 옵션 뒤에 함께 쓴다. `--rust target1 --rust target2`는 마지막 옵션만 적용되므로 사용하지 않는다. 신규 배정과 종료 후 승인된 재개부터 이 계약을 읽고, 이미 실행 중인 검사는 취소하거나 같은 입력으로 반복하지 않는다.
- 배정된 선택 E2E도 `flock /home/ubuntu/.cache/grove-rust-check.lock python3 scripts/build.py test --e2e ...`로 서버·웹 빌드부터 브라우저 종료까지 전체 명령을 직렬화한다. 메인의 E2E도 같은 잠금을 써야 한다. 기능 workspace는 E2E 포트·공용 target·검사 설정을 바꾸지 않고, 기존 서버를 중단하지 않는다.
프로젝트의 해당 선택 검사 진입점을 사용한다. 환경이 없으면 설치나 우회 대신 미실행으로 기록한다.
시험은 작성하되 미실행을 통과로 보고하지 않는다. 연결 없는 모듈이 기존 검사에서 제외된 사실을 숨기지 않는다.
각 worktree에 target·node_modules·툴체인을 통째로 복사하거나 설치하지 않는다.
다운로드 cache는 기존 정책을 유지한다. 큰 산출물 생성은 이번 독립 단계에서 하지 않는다.
실제 사용자 데이터·자격증명·서비스·유료 모델·외부 시스템에 부작용을 일으키지 않는다.

## 완료 인계: 사용자에게 결과 복사를 요구하지 않기
사용자가 요청한 인계 파일 `work/RESULT-NN.md`를 자기 worktree 안에 작성한다.
맨 앞 8 KiB 안에 다음 완료 계약을 넣는다. 이는 통합 담당이 맡은 E2E까지 통과했다는 뜻이 아니며, 아래 명령·결과 근거를 대체하지 않는다.

```text
<!-- grove-handoff:v1
{"state":"ready","remaining":[],"blockers":[],"integration_checks":["통합 담당이 실행할 정확한 E2E spec·공통 인수"]}
-->
```

- `ready`: 소유 범위의 구현·연결·선택 검사가 끝났고 실행 가능한 미완료나 blocker가 없다. 중앙 E2E 등 합의된 통합 인수만 `integration_checks`에 남길 수 있다.
- `needs-work`: 실행 가능한 잔여를 `remaining`에 적는 중간 상태다. 이 상태로 정상 종료하지 않는다. 중단·인계가 불가피했으면 메인이 원래 종료 세션의 이어하기 대상으로 처리한다.
- `blocked`: 독립적으로 가능한 일을 모두 끝냈고 실제 승인·외부 환경만 남았다. `remaining`은 비우고 `blockers`에 `{"reason":"실제 막힌 조건","unblock":"정확한 해제 조건"}`을 적는다. 부분 구현을 완료로 바꾸거나 같은 blocker로 자동 재개를 반복하지 않는다.
- 과거 자유 형식 인계는 완료나 재개를 추측하지 않고 메인이 한 번 분류한다. 재개 시 기존 인계·소스·통과 근거를 재사용하고 이 계약을 갱신한다.

다음 내용을 빠짐없이 포함한다:
- 배치/번호, worktree 절대 경로, branch, 공통 기준 SHA.
- 제공 동작, 소유 변경 파일, 구현 종료·통합 대기·blocker 중 현재 상태.
- public export/props, 입출력·오류·권한 계약, 공통 파일에서 필요한 연결.
- 실제 실행한 검사 명령·입력·결과, 실패·미실행과 이유.
- 검사 근거를 재사용할 수 있도록 검사 시점 코드와 이후 변경 파일을 구분한다. 실행기가 제공한 wall/CPU 시간은 그대로 인계하되, 없는 시간이나 절감량을 추정해 채우지 않는다.
- TODO ID별 전체 요구 충족 근거, 부분 완료·남은 요구. 미검증 항목을 완료 후보로 단정하지 않는다.
- 남은 위험·환경 제약, 다음 통합 단계.

RESULT 자체에 그 파일을 포함한 커밋 SHA를 써서 순환 수정하지 않는다.
로컬 커밋이 승인돼 있으면 관련 코드·시험·RESULT만 함께 커밋하고 한국어 메시지를 사용한다.
최종 채팅에는 완료 SHA와 RESULT 절대 경로, blocker 유무만 짧게 알린다.
커밋 승인이 없으면 파일은 남기고 미커밋임을 명시한다.
이후 편집을 멈춘다. push·merge·배포·서비스 중단·다른 기능 착수는 하지 않는다.
`TODO.md`는 기능 담당이 체크하지 않는다. 통합 담당이 실제 연결·필수 검증 후 반드시 체크하며 미완료는 남긴다.
통합 담당은 인계 보존·검증 후 완료 worktree와 Paseo 워크스페이스를 정리한다. 기능 담당은 직접 삭제하지 않는다.
