## 사용자 흐름·소유
`REC-012`의 남은 기록 경계별 디스크 부족·쓰기 권한 실패를 끝낸다. 기존 강제 종료·실행 epoch·원문 보존·비재호출 근거는 재사용한다. `tests/recovery.rs::actual_sqlite_full_stops_live_work_and_restart_keeps_the_result_unknown`의 실제 SQLite full 방식과 기존 복구 fixture를 확장한다.
소유는 신규 `tests/recovery_faults.rs`, 기존 `tests/recovery.rs`의 해당 기록 경계 시험, `src/runner.rs::{write_evidence,recover_on_start,read_evidence,recovery}`의 재현된 결함 최소 수정, `work/RESULT-44.md`다. fixture가 필요하면 전용 시험 파일 안에 둔다. 공용 store·실행 루프·load_step·도구 schema·hook·fallback·context/압축·다른 시험 helper는 읽기 전용이다. 실제 결함 때문에 다른 경계가 필요하면 이유·정확한 연결을 blocker로 인계하고 독립 범위를 끝낸다.
실제 조회는 기존 `GET /recovery`·턴 조회/검토 API와 `RecoveryPanel` 계약을 사용한다. 새 route·UI·DB schema·의존성·일반 fault-injection framework는 만들지 않는다.

## 안전·복구·인수
각 실패는 소유가 확인된 disposable DB/디렉터리와 fixture에서만 주입한다. 공유 디스크를 채우거나 호스트 권한·공유 환경·서비스를 바꾸지 않는다. Unix 권한 시험이 실제 실행 사용자에서 쓰기를 거부하는지 관측하고, chmod만 했다는 이유로 실패를 주입했다고 간주하지 않는다.
관측한 원본/증거·확정 receipt·살아 있는 owner_epoch를 보존하고 기록 실패를 성공으로 숨기지 않는다. 재시작 반복이 모델·도구 재호출/중복 결과를 만들지 않아야 한다. 기존 실제 SQLite full 성공 근거를 각 기록 경계 전체의 성공으로 확대하지 않는다.
선택 Rust는 전용 recovery_faults와 영향받은 recovery 회귀다. 기존 API fixture로 실패→복구 목록/검토→반복 재시작을 끝내며 UI 변경 없는 서버 흐름에 억지 브라우저를 추가하지 않는다. COMMON의 공유 환경과 전체 Rust/E2E 잠금을 따른다.
완료는 실제 기록 실패에서도 조회 가능한 원본·결과 불명·실행 소유권을 유지하고 재시작이 수렴하는 상태다. 구현 가능한 잔여를 끝내고 `grove-handoff:v1`·실제 근거·blocker(reason/unblock)를 RESULT에 남긴다. 관련 한국어 로컬 커밋 허용. TODO 체크·merge/rebase·push·배포·재위임·workspace 관리·dependency 변경은 하지 않는다.
