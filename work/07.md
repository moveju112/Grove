## 고정 계약
기존 `src/update.rs`와 설치·업데이트 계약을 읽고 중복 updater를 만들지 않는다.
입력은 명시적 검증 바이너리·설정·서비스 대상이다. 서비스 이름과 경로를 엄격히 검증한다.
계획 출력과 명시적 적용을 구분한다. 직접 실행 서버와 등록 서비스의 소유권을 혼동하지 않는다.
등록·해제 반복과 부분 실패 후 재실행이 수렴해야 한다.
다른 소유 서비스나 사용자 unit을 임의로 덮어쓰지 않는다.
해제 시 대화·설정·자격증명·바이너리를 기본 삭제하지 않는다.
systemd 미지원이면 한계를 명시하고 가짜 성공을 반환하지 않는다.

## 시험·제외
현재 호스트의 systemd·linger·실제 서비스는 호출하거나 변경하지 않는다.
시험은 임시 경로와 주입 가능한 명령 실행기로 등록 계획·실패·반복·소유권·데이터 보존을 확인한다.
실제 systemd 미검증을 명시한다. Windows·root·production·바이너리 재빌드·배포는 제외한다.
서버 build를 유발하지 않는 기존 Python 단위 시험 형태로 구현한다.
