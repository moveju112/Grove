## 사용자 흐름·소유
`RTE-012`: pause/resume/run-once·취소·budget 초과·동일 webhook·담당 봇 변경을 기존 routine 화면과 실제 서버에서 끝낸다. 기존 `RTE-004/005/009~011`·webhook 재시작 비재실행 근거는 재사용한다.
소유는 `src/schedules.rs::{pause,resume,run_now,update,runs,receive_hook}`의 재현된 수명주기 결함 최소 수정, `tests/schedules.rs`의 관련 회귀와 신규 `tests/routine_lifecycle.rs`, `web/app/components/SchedulesPanel.tsx`의 기존 제어/표시, 신규 전용 `web/e2e/routine-lifecycle.spec.ts`, `work/RESULT-47.md`다. 작은 전용 UI helper/단위 시험은 신규 `web/app/components/routine-lifecycle/` 안에 둘 수 있다.
기존 route·봇/세션·revision·멱등 receipt·예산·승인·outcome 분류 정본을 사용한다. 새 route·DB schema·공용 API client·state/CSS·runner·approvals·봇 구현·실행 정책은 읽기 전용이다. RTE-007의 미정인 결제/영구삭제 분류 정책을 새로 만들거나 완료라고 표시하지 않는다.

## 권한·복구·완료
routine 중지는 미래 예약 중지와 현재 실행의 취소 요청을 구분한다. 이미 실행한 부작용을 되돌렸다고 표시하지 않는다. budget 초과·승인 대기/거부·unknown을 성공 처리하지 않는다. 동일 webhook/응답 유실/재시작/담당 변경이 이미 시작한 턴을 다시 실행하거나 다른 봇으로 바꿔 실행하지 않도록 기존 고정 identity를 유지한다.
관리 작업은 기존 Owner·대상 범위·revision·멱등 계약을 유지하고 stale/late 응답이 다른 routine/프로젝트 화면을 덮어쓰지 않는다. fixture는 소유 임시 DB·loopback 모델/webhook만 사용하며 실제 봇·예약·외부 알림 서비스는 변경하지 않는다.
배정 브라우저는 전용 routine-lifecycle spec의 pause→재개→1회 실행→취소/결과 확인과 담당 변경·중복/응답 유실 보존 흐름이다. 필요한 서버 회귀와 UI 단위/타입 검사를 함께 소유한다. COMMON의 전체 Rust/E2E 잠금·공유 환경을 따른다.
완료는 실제 화면의 제어와 서버 실행 상태·예산·비재실행이 일치하고 중지/부작용의 의미를 구분하는 상태다. 실행 가능한 잔여를 끝내고 RESULT에 `grove-handoff:v1`·근거·실제 blocker(reason/unblock)를 남긴다. 관련 한국어 로컬 커밋 허용. TODO·merge/rebase·push·배포·재위임·workspace 관리·dependency 변경은 하지 않는다.
