## 안전·오류·복구 계약
관리 mutation은 기존 `Owner`, `expected_revision`, 멱등 receipt를 따른다. 시작 소유자·서버·issuer/resource·등록된 정확한 redirect에 일회용 state와 PKCE를 결합한다. callback은 state·기한·소유자·서버 revision을 검증하고 중복·취소/만료 뒤 늦은 완료·변조를 거부한다. 외부 callback을 앱 인증 우회나 임의 URL 전달 경로로 만들지 않는다.
승인 URL과 scope·전송 대상을 사용자에게 보여 주고 사용자가 명시적으로 연결/갱신하게 한다. 임의 endpoint/redirect·비밀 원문 URL·token 노출을 막고 기존 민감 헤더·redirect 금지·credential redaction·vault 암호화 경계를 지킨다. 외부 자격/응답 본문은 로그·DB 감사·화면·모델 입력에 노출하지 않는다.
설정/자격 변경은 기존 실행 중 제한과 MCP catalog/승인 identity를 보존한다. 승인 identity가 달라지면 기존 승인을 재사용하지 않고 새 연결 확인·승인을 요구한다. 토큰 갱신은 동일 자격 기준으로 직렬화하고 자동 무한 갱신·도구 재전송을 하지 않는다.
token 교환/갱신의 응답 유실·timeout·중단은 unknown으로 보존하고 자동 반복하지 않는다. 재시작·취소 경합·늦은 callback이 잘못된 자격을 활성화하거나 도구를 재실행하면 안 된다. OAuth 완료·MCP 연결 검사·도구 실행 성공을 서로 구분한다.
stdio/기존 secret 헤더 방식의 동작·명시적 구 SSE 지원을 유지한다. TTS·재생·마이크 차단과 STT 제외를 보존한다. 실제 issuer/서비스 변경·운영 데이터·원격 설치·실제 토큰 발급은 하지 않는다.

## 검증 소유·완료
로컬 issuer/MCP fixture로 시작·권한·상태·취소·만료·완료·명시적 갱신, callback 재사용/변조·revision 경합·취소 뒤 완료·재시작·실제 응답 유실·unknown 비재실행·credential 가림·기존 MCP transport 회귀를 선택 검사한다. 새 spec에서 UI 시작부터 연결 검사와 승인된 로컬 도구 호출까지 이어진 사용자 흐름을 검증한다. 모듈만 만들고 연결/브라우저 인수를 메인에 넘기지 않는다.
