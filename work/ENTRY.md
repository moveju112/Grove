# 병렬 작업 자동 진입

사용자가 이 문서로 시작하라고 요청하면, 이전에 잘못 지정한 번호 문서 대신 현재 worktree에 맞는 문서를 선택한다.
숫자 추측이나 세션 제목이 아니라 실제 Git worktree 경로와 브랜치를 기준으로 한다.
이 파일 자체는 커밋·push·merge·배포 권한을 부여하지 않는다. 사용자의 실행 프롬프트에 명시된 권한을 따른다.

## 판별 절차
원본 프로젝트 `<원본 저장소>`의 `main`에서 사용자가 통합·정리·다음 작업 준비를 요청했다면 기능 번호를 매칭하지 않고 `work/INTEGRATE.md`로 진입한다. “00 메인 세션”이라는 이름도 이 조건에서만 메인 역할로 해석한다. 아래 절차는 기능 작업 시작 요청에 적용한다.

1. 현재 디렉터리에서 Git top-level 절대 경로, 현재 브랜치, Git 상태를 조회한다. 하위 디렉터리에서 시작해도 top-level로 판단한다.
2. `<원본 저장소>/work/README.md`의 “준비 완료된 워크스페이스” 표에서 **top-level 절대 경로와 브랜치가 모두 일치하는 행**을 찾는다.
3. 정확히 한 행이 일치하면 그 번호를 선택한다. 세션 제목·이전 메시지의 번호·디렉터리 이름 일부만으로 고르지 않는다.
4. `<원본 저장소>/work/COMMON.md`와 `<원본 저장소>/work/NN.md`를 읽는다. NN은 선택한 두 자리 번호다.
5. 번호 문서의 경로·브랜치가 실제 상태와 일치하고 공통 기준에서 분기한 작업인지 확인한 뒤 해당 작업을 시작한다.
6. 사용자에게 선택된 번호와 기능을 한 줄로 알리되, 일치가 확인되면 추가 승인을 묻지 않고 진행한다.

## 실패·재개
- 06은 사용자 결정으로 취소됐다. 이전 지시나 남은 브랜치가 있더라도 작업을 시작·재생성·재배정하지 않는다.
- 매칭 없음·둘 이상·detached HEAD·문서 간 불일치이면 편집하지 않고 실제 경로·브랜치와 이유를 보고한다.
- 매칭 없음으로 멈출 때는 마지막 줄에 “README 표가 갱신된 뒤 같은 첫 메시지를 다시 보내면 된다”고만 안내한다. 다른 세션의 보고를 붙여 넣게 하지 않는다. 다른 worktree의 보고가 들어오면 자기 상태와 구분해 한 줄로 답하고, 다시 판별한다.
- 원본 프로젝트 `<원본 저장소>`에서는 기능 작업을 시작하지 않는다.
- 매칭을 맞추려고 다른 worktree로 이동하거나 브랜치를 바꾸거나 새 worktree를 만들지 않는다.
- Git 변경이 있으면 자기 작업의 재개인지 기존 인계와 대화로 확인한다. 불명확한 변경을 인수·삭제·덮어쓰지 않는다.
- `work/RESULT-NN.md`가 이미 있으면 실제 코드·Git 상태와 대조한다. 완료한 작업을 자동 반복하거나 다른 기능으로 확장하지 않는다.
- 번호가 잘못된 기존 지시로 편집 전에 중단했던 세션도 이 절차로 다시 판별해 진행할 수 있다.

## 완료
선택한 번호 문서와 COMMON에 따라 구현하고 자기 worktree에 `work/RESULT-NN.md`를 남긴다.
통합·검증·TODO 갱신·완료 작업 정리·다음 번호 준비는 원본 프로젝트에서 `work/INTEGRATE.md`를 실행하는 메인 세션이 수행한다. 기존 00 기능 worktree와 사용자가 부르는 “00 메인 세션”은 구분한다.
