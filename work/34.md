## 고정 계약
- 정책은 실제 role identity에 묶고 존재하지 않는 역할·잘못된 형태를 기존 고정 오류 형식으로 거부한다. 기본 설정은 현재의 위임 동작을 유지한다.
- 서버·프로젝트·대화의 정책은 상위 금지를 하위 범위에서 넓힐 수 없다. enabled·정의 상태·최대 깊이·부모/run 소유권도 계속 검사한다.
- 허용되지 않은 역할을 모델 안내에서 제외하고, 직접 spawn·기존 자식 send 우회도 서버에서 막는다. 승인 대기 중 정책을 철회하면 실행 직전 재검사에서 막혀야 한다.
- 금지 뒤에도 기존 작업의 조회·대기·취소와 완료 결과 보존은 가능하다. 정책 변경이 이미 끝난 작업을 재실행하거나 새 자식을 자동 생성하면 안 된다.
- `Principal`, `expected_revision`, `idem::run`, 기존 승인 identity·취소·재시작 비재실행을 유지한다. 정책 오류·권한 거부·응답 유실을 성공이나 재실행으로 바꾸지 않는다.
- 역할별 모델·thinking·fallback, 기본 지침 변경, orchestration 엔진 교체는 제외한다. TTS·재생·마이크 차단은 보존하고 마이크/STT·취소된 06을 되살리지 않는다.

## 검증 소유와 알려진 별도 실패
정책 행렬·범위별 축소·모델 안내·직접 spawn/send·승인 대기 중 철회·기존 작업 조회/취소·재시작/응답 유실의 선택 Rust 회귀와 필요한 타입 검사를 맡는다. 실제 settings 저장부터 허용/금지 위임까지 `e2e/agent-policy.spec.ts`도 작성·실행한다.
모든 Rust/E2E 전체 명령은 COMMON의 공용 환경과 `/home/ubuntu/.cache/grove-rust-check.lock`으로 직렬화한다. 유효한 입력의 기존 검사 결과는 재사용하고 실패·영향 검사만 다시 실행한다. 로컬 fixture만 사용하고 실제 계정·유료 모델·서비스에는 부작용을 만들지 않는다.
기존 공통 인수에서 `SETTINGS-021` 직접 링크 스크롤 E2E가 실패했다. 이 작업은 그 설정 화면의 50ms 이동 로직을 소유하지 않으며 무관한 실패를 숨기거나 함께 고치지 않는다.
