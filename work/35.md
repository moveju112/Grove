## 안전·복구 계약
DB의 이미 가려진 결과·도구 상태·화면 원문을 복구 정본으로 보존하고 파일은 재생성 가능한 사본으로 둔다. 파일 보관 경로는 data_dir 안의 전용 경로에 두며 사용자 지정 임의 경로를 읽거나 덮어쓰지 않는다. 파일 누락·쓰기 실패가 원래 도구의 성공/실패/unknown을 바꾸거나 재실행을 일으켜선 안 된다.
참조는 경로 문자열이 아니라 영속 call identity에 결합한다. 현재 대화와 이미 허용된 fork 이력 안에서만 조회하며 다른 대화·프로젝트 결과를 call ID 추측으로 읽을 수 없어야 한다. 기존 인증·도구 정책·읽기 전용·활성 실행 root 경계는 유지한다.
발췌와 범위 조회에 UTF-8 경계·요청/응답 크기 제한·유한 범위를 둔다. 잘린 결과 자체를 완전한 원문이라고 표시하지 않는다. 기존 출력 상한을 올리거나 비밀 가림을 우회하지 않는다. 조회 도구의 큰 결과가 자기 자신을 무한 offload/재조회하도록 설계하지 않는다.
DB 원문과 `messages.model_input` 분리, tool call/result 짝과 오류 상태를 보존한다. 읽기 실패는 명시적 오류이며 빈 성공으로 숨기지 않는다. 재시작·snapshot 복구 뒤 캐시가 없어도 DB 정본에서 복구하며 도구 부작용을 다시 실행하지 않는다.
새 dependency·runner/compaction/fallback 교체·임의 파일 다운로드 UI·실사용자 데이터 이관은 제외한다. TTS·재생·마이크 차단과 STT 제외는 유지한다.

## 검증 소유·완료
실제 tool-request→실행 결과→모델 발췌/참조→허용 범위 조회 사용자 흐름과 인증/권한·fork 경계·UTF-8·상한·오류 상태·파일 누락/저장 실패·재시작 복구의 선택 Rust 검사를 맡는다. 새 브라우저 spec에는 로컬 fixture 결과를 화면 원문과 모델 표현에서 구분하고 재조회·reload 비재실행을 확인한다. API·모델 입력은 실제 경로를 쓰고 외부 모델/서비스·실제 계정은 호출하지 않는다.
원본 COMMON의 공용 환경·공유 target와 Rust/E2E 전체 명령의 `grove-rust-check.lock` 직렬화를 따른다. 유효한 동일 입력 검사는 반복하지 않는다. 코드 연결·선택 검사·자기 결함 수정을 소유 workspace에서 끝낸다.
완료는 큰 결과의 나머지가 실제로 조회 가능하며 출력/권한/복구 경계와 원래 도구 결과가 보존되는 상태다. `grove-handoff:v1`·검증·실제 blocker(reason/unblock)를 RESULT에 남기고 관련 한국어 로컬 커밋 후 종료한다. TODO 체크·merge·push·배포·workspace 정리·재위임은 하지 않는다.
